## Entry 4 — Redesign the login page (first screen from the two 2026-10-03 reviews)

- **time:** 08:45
- **agent:** Claude Code (Opus 5.5)
- **task:** Redesign `/auth/login` using the UI/UX Pro Max and anti-ui-slop skills, based on both review docs in `docs/reviews/`
- **status:** completed
- **scope:** apps/web
- **touches_money:** no

### What changed
- Branch `feat/login-redesign` created from `master` (not committed).
- `apps/web/app/auth/login/page.tsx` — new layout: teal-700→600 brand band with logo, white sheet, `h1` + helper copy, one joined "Mobile number" control (country trigger + number input), error in a reserved slot with an icon, "Change number" as a 44px text link, server-error banner, 52px `primary` CTA right under the form with a spinner + "Checking your number…" while pending, typo-fixed terms line. On `sm+` it's a 448px card on the `canvas` background. No longer wrapped in `components/layout/Page.tsx`. Added a focus-first-invalid-field effect (§5.3.6). Formik/Yup/mutation/redirect/localStorage logic is unchanged.
- `apps/web/app/globals.css` — `:root` `--primary` → `#0f766e` (teal-700), `--primary-foreground` → white, `--ring` → `#14b8a6`, new `--canvas` / `--color-canvas` (`#f6f8f8`). `.dark` untouched.
- `apps/web/lib/fonts.ts`, `apps/web/app/layout.tsx` — Plus Jakarta Sans (400–700) replaces Inter + all-weights Poppins **app-wide**. `--font-sans` and `--font-heading` both point at it. Metadata title is now "Kimo Wallet".
- `apps/web/components/ui/button.tsx` — new `primary` variant (`bg-primary`). `default` (white) is unchanged because QR and Register put it on teal.
- `apps/web/components/country-code-select.tsx` — trigger gets an `aria-label` ("Country code: Indonesia +62"). Sheet close button is now 44×44 with `aria-label="Close"`.

### Why
Both reviews flagged the full-teal login: white text on `#14B8A6` is about 2.5:1 (fails AA), there's a big empty gap between the fields and the CTA, the "Change number" pill competes with Continue, the error slot jumps, and there's a typo. Teal-700 was chosen as `--primary` for contrast (~5.5:1 with white). The CTA was first pinned to the bottom, but on render that recreated the empty gap the critique complained about, so it now sits right after the form. The UI/UX Pro Max `--design-system` output (gold/purple) was not used; see Entry 3.

### Invariants affected
none. The `--primary`/`--ring` change touches every consumer: Badge `default` (overridden to green in `TransactionRow`), Avatar badge, `link` variants, and every focus ring, which is now teal instead of grey.

### Verification
- Rendered `/auth/login` in Chrome at a 500px viewport: default state, empty-submit error state, and country sheet open. DOM read after the failed submit: `focused: true`, `aria-invalid="true"`, group `border-top-width: 1px` with the destructive colour, input `font-size: 16px`, CTA height 52, "Change number" height 44, sheet close 44×44 with label, body font "Plus Jakarta Sans".
- Desktop: `resize_window` didn't change the viewport (stuck at 500px), so the page was rendered inside a 1280px-wide iframe and screenshotted. The card is centred on the canvas.
- `/auth/register` re-rendered: unchanged apart from the font.
- **Not seen:** the pending/spinner state and the server-error banner (both need a live login call), and the signed-in screens after the font/token change (they need a session).
- `npm run lint` → 0 errors, 1 warning (`react-hooks/exhaustive-deps` on the existing `userData` redirect effect, pre-existing, not touched).
- `npm run build` → compiled, TypeScript passed, 9/9 pages generated.

### Known gaps / TODO for the next agent
- `/auth/register` still uses the old full-teal layout, so login and register now look different. It's the natural next screen to redesign.
- "Change number" still has no handler (it didn't before either); it needs a product decision.
- `localStorage` is still read during render (unchanged).
- Home/QR/History/Transfer haven't been checked visually against the new font and teal focus rings.

### Do NOT do
- Don't change `Button`'s `default` variant to teal; QR and Register render it on a teal background. Use `variant="primary"`.
- Don't use `bg-primary`/white text on `kimo-500`; teal-500 is decoration/ring only.
- Don't move the login CTA back to `mt-auto`; it recreates the empty gap the critique flagged.

### What changed
- `apps/web/features/auth/components/auth-shell.tsx` (new): the brand band + white sheet + `sm+` card frame, moved out of the login page.
- `apps/web/features/auth/components/phone-number-field.tsx` (new): joined country-code + number control with one label and one error line.

Heading "Create your Kimo account", Full name field with hint "10–50 characters, shown to senders.", `primary` CTA "Create account" with a spinner + "Creating your account…" while pending, server-error banner for errors other than "phone number is already registered" (that one still goes on the number field), and a new "Already have an account? Log in" link to `/auth/login`.
- `apps/web/app/auth/login/page.tsx`: refactored onto the same components. Rendered output is unchanged from Entry 4.
- Both pages: focus-first-invalid-field moved out of a `useEffect` into the form submit handler (`formik.handleSubmit` then `formik.validateForm()`). Reason: an effect keyed on the error fields would steal focus while the user types in another field, and one keyed only on `submitCount` trips `exhaustive-deps`. This **corrects Entry 4**, which used the effect.
- `features/auth/schemas/{login,register}.schema.ts`: `country` required-message "This field is required" → "Select your country code". It now shows under the combined phone field, where the generic message didn't say which part was missing. Copy only, no rule change.

### Why
The user asked for register to match login. Both reviews flagged the same issues on register as on login: full-teal background, white-on-teal-500 contrast, layout-jumping error slots, the "you are agree" typo, and no way back to login. Extracting the shell and phone field keeps the two screens from drifting, and they live in `features/auth/components/` per the feature-first rule.

### Invariants affected
none (no money, auth, contract or migration changes; register/login request logic untouched).

### Verification
- Chrome, desktop viewport (~1440px): register default state, and register empty-submit (country and full-name errors shown, focus on `register-number`, full-name border 1px destructive, 52px high, 16px font).
- Register with `localStorage.phoneNumber = "ID-81234567"` (the same prefill the login→register redirect writes): country/number prefilled, and empty-name submit focuses `register-full-name`. The test key was removed afterwards.
- 390px and 360px iframes: register and login side by side. Hint is one line (21px) at 360px; `scrollWidth` equals 360 (no horizontal overflow).
- Login after the refactor: empty submit → focus `login-number`, error "This field is required".
- `npm run lint` → 0 errors, 1 warning (existing `router` dep on the login `userData` redirect effect).
- `npm run build` → the first run **failed** TypeScript (`boolean | undefined` passed to `invalid`). Fixed with `!!` coercion; the re-run compiled, passed TypeScript, and generated 9/9 pages.
- **Not seen:** the pending spinner, the server-error banner, and a successful registration redirect (all need live API calls).

### Known gaps / TODO for the next agent
- Register's `fullName` schema requires **min 10 characters**, which rejects real short names (e.g. "Ani Lim", 7). Flagged, not changed; it's a product rule.
- "Change number" on login still has no handler.
- `localStorage` is still read during render on both pages (unchanged).
- Signed-in screens still use the old full-teal layout and haven't been checked against the new font/tokens.

### Do NOT do
- Don't put focus-on-error back into a `useEffect` that depends on `formik.errors`; it steals focus mid-typing.
- Don't make the full-name hint longer; anything past one line at 360px makes the slot shrink when the one-line error replaces it.
